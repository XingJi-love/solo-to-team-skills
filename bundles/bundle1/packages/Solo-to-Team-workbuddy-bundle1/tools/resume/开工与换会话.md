# 中断后，接着做 · 1.3 / Resume from the existing work · 1.3

[English instructions](README.en.md) · [Open the English reader](从这里续办.html#en)

将本目录保存在本单专用的共享文件夹。双击[从这里续办](从这里续办.html)。两个宿主都使用同一份断点和已保存的工作文件，业务席之间沿原来约定的权限接力。

**开工时发给首席**

> 把本单原要求、最新变更（无则写“无”）、原交还入口、不可重做的已过项和下一具体责任人记入 checkpoint.json。产物保存后记真实版次和 SHA-256。已有的独审、交件、实收分别取原席记录，不替其他席出回执。请在中断前把最新断点和实物保存到本单共享文件夹。

空白模板的 `next.owner` 默认为 `lead`。写断点或在网页填写时，首席用 `lead`，生产官用 `producer`，审核官用 `reviewer`，接收席用 `recipient`。旧断点曾把审核官写成 `review`。这个别名自 1.1 起兼容，当前版本为 1.3，本包为文案修订 1.3a。若席位拼错，页面会提示去哪里改，并继续核已有文件。真正接哪一步以核到的产物、独审、交件和回执为准。此前填写的下一棒及动作只供对照，不会授权派工。

**换会话时发给接手首席**

> 先核共享文件夹的 checkpoint.json 和实际文件，找回已有进度。产物变了先比差异；没核审只补同版独审；有独审而未交只补原入口交件；已经送出只查同次实收。若产物、独审、交件与真实接收记录吻合，就结束。文件缺失先找回；不要重开整单、重复发送或联系无关席位。

## 普通用户怎样用

1. 首次可用空白的 [checkpoint.json](checkpoint.json)。在页面展开“填写或更新”，填任务四项。原任务、变更和交还入口在两端原样使用；页面会算出范围 SHA-256。已做过的事和不可重做清单可各写一行。
2. 有实际产物时，填版次后在“产物”行点“登记这份文件”。其他三行分别登记已保存的原始独审、交件和目标接收记录。**只登记已经发生的环节**。有证据线索但暂时拿不到文件，应保留原有文件名和指纹，或在“下一具体动作”写明去哪里找。
3. 另存断点，将最新副本放进同一共享文件夹；不要意外拿旧下载副本续办。换会话时打开最新 JSON，通过多选一次选齐已有文件。只核对时用上方“选择已保存的文件”；下面的“登记”会更新草稿指纹。
4. 以页面上方的核收结果接棒。出现同名候选时只选正确的一份；只有名字和返回文字，仍须找回实物。若两端同时接手，由既有首席先指定唯一执行人；该阅读器不管理宿主锁，也不会发送或重试任务。

## 让现有记录可以交叉核对

在各自已有的 Markdown 或 UTF-8 纯文本记录末尾另起一行，写入 `CHECKPOINT ` 加一个单行 JSON。应有真正的宿主记录正文，说明**谁在何处、核了或收了什么**。用脱敏的原消息/附件标记作 `source_ref`，以后可回原入口查。每个文件对同一 kind 应有一个明确绑定。现有格式不能追加时可保存原席原记录的脱敏转录，保留可查的出处及必要上下文；要标清转录，勿冒充平台原件。

在页面上展开“原席出记录”，选自己正在出具的记录类型，点击“复制绑定草稿”。整行来自当前断点和实际选中的文件。任务、版次、范围、实物 SHA-256 与交还目标均已填写。目标直接沿用原委托的写法，括号解释、所在窗口等信息写在正文。

原出件人自己补三栏。审核席在独审后写 `actor=reviewer`、可查出处 `source_ref` 与真实结论 `pass` 或 `revise`。首席实际送出后写 `actor=lead`、原送件位置和 `sent`。接收席实际打开送来的实物后写 `actor=recipient`、原收件位置和 `received`。保留记录正文，空白草稿不能证明任何一方完成了工作。生成实收草稿时，同时选择登记的原交件记录，页面会核其目标、范围、版本、实际字节，生成对应的 `dispatch_sha256`。

若核收指出 `dispatch.target` 不符，先查实际送达的是哪个入口。当原窗口正确、只是绑定栏多写了说明时，原发件席用草稿更新绑定行，保留原发件位置及更正前的记录，把说明放正文。在断点内登记更正文件的指纹；若已有实收记录，请接收席核它引用哪份交件凭据。不需要为修字段重发产物或重做审核。若实际送错对象，应回到原席查明经过，不能只改栏位。

文件指纹是原始字节的 SHA-256。范围指纹按 `[task.id, task.request, task.latest_change, task.return_to]` 的紧凑 JSON 数组（UTF-8、不另加换行、原中文保留）计算。改了原要求或最新变更，此前的审核不会自动变成对新范围有效。实收文件要独立于其引用的交件文件，避免循环引用。产物、记录能证明到哪一步，就停在那一步；本工具核字节及记录对应关系，记录来源的真实性仍由原席或宿主查证。
