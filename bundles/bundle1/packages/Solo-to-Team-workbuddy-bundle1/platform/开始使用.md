# WorkBuddy：采用协作 Skill

当前候选 `0.1.0-rc.5`。它增补完整 MAS，原16席、6群、建队台、团队配置和四个原 Skill 保留。装 Skill 不会自动注册专家团或给全员加载正文。

## 采用前先核两件事

- 使用你已有、能正常对话的 WorkBuddy。**本机此前原生安装核到的是用户级 Skill，不是只对当前对话生效；单独项目不构成技能隔离。** 同一用户的其他任务可能发现这项技能。先确定这就是本次采用范围，沿用已有适用授权，不为同一动作重复审批。
- 先在技能列表核对 `solo-to-team-workbuddy` 是否已存在及其版本。同版且已核可用直接复用；不同版保留旧版本的可恢复内容，按已有替换依据处理。没有替换依据或无法确认目标对象，就先不上传覆盖。名称相同不能证明内容相同。

## 拿对文件并调用

以下上传步骤用于首次安装；已有同名不同版时，先看下方的更新说明。

1. 外层完整 MAS ZIP 先解压。选择本目录的 [solo-to-team-workbuddy.zip](solo-to-team-workbuddy.zip)，**这份内层 ZIP 不解压后上传，也不上传整个 MAS 主包**。
2. 在 WorkBuddy 走“添加技能 → 上传技能”，选这份单技能 ZIP；核名称、实际安全检查提示与安装／启用结果。有同名冲突提示时回到上面的版本核对，不连续覆盖求通过。
3. 在目标任务请它使用 `solo-to-team-workbuddy`，从实际安装位置读本版 `SKILL.md` 和本单适用的 `references/roles.zh.md`、`references/groups.zh.md`。资源随包不等于已经读入；每位实际成员分别核需要的材料。

ZIP 中一个顶层技能文件夹，含主文、两份参考、`assets/team.text.zh.json` 和 LICENSE。JSON 是建议数据，不是专家团原生注册文件。需要成员时，沿用已有团队；没有团队再按[原 MAS 团队采用说明](../tools/team-16/SETUP.zh.md)建立／绑定。本页不新增成员、权限或账号。

> 请使用 solo-to-team-workbuddy 接手这份半成品，沿用已确认要求，安排真实制作和独立审核，把可打开的成果交回当前对话。先核可用执行者与已有授权；分别核正文、适用参考和实际回件。

## 已有同名不同版：本机5.9.3的更新路径

本机 WorkBuddy 5.9.3 这次上传同名 ZIP 时，安全检查显示“安全”，但继续安装被拒绝，提示已存在同名技能；旧件没有改变。安全检查结果不等于更新完成，不重复导入求通过。以下编辑路径只在本机该版本核过，不能承诺所有 WorkBuddy 版本相同。

1. 先保留目标技能旧版内容、版本及文件指纹。在已有确切替换授权下更新，不重复审批；若目标或替换范围不明，先保留旧版。
2. 打开**同一张已安装技能卡 → 更多 → 编辑**。本次实际打开的是携带 `skill-creator` 和目标 Skill 的原生任务，不是单独的“编辑保存”按钮。让该任务先核旧文件与新来源的指纹，再只更新已确认的差异文件。旧指纹不符时，不覆盖可能已由他人改过的内容，先核清变化。
3. 此前 rc3 → rc4 的本机更新只改过 `SKILL.md`，这是历史观察。采用当前 rc5 时，先逐件对照实际旧件与本包来源清单，只替换已确认的差异文件；没有差异的资源与原生安装元数据保持不变。更新后的文件须与所选 rc5 来源逐字一致。不要扩成重装整个技能库、改账号设置或猜私有接口；找不到相同原生入口时保留现状，说明实际缺口。
4. 重新打开同一张安装卡，核版本 `0.1.0-rc.5` 和新规则；再用新任务核实际加载及按题输出。库卡显示不能证明运行中的旧任务全部刷新，也不替代原任务可打开成果的收件验收。

## 失败与撤回

上传未完成时停止该次提交，保留原包和错误；先核实际是否已经保存，不重复上传。已保存后发现问题，停止继续调用本版，保留旧件和本次变更记录；只对确切的本次新增／更新对象使用宿主实际提供且已核清的停用或恢复入口，并读回结果。**本轮没有核实统一适用的卸载按钮位置或旧版恢复契约，不编造操作步骤，也不把“没再调用”说成已经卸载。** 找不到可靠入口时，报告具体未撤回项，不删技能库、不改权限、不拿其他客户端代办；已经产生的业务成果保留。
