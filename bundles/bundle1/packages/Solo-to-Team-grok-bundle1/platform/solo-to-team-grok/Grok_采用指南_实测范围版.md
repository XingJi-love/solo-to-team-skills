# Grok 采用指南（实测范围版）


> 包装与采用范围：外层 MAS 与 adapter.5 交付包须先解压；真正附给目标 Bot 的是本目录 `solo-to-team-grok_design-2-doc-1_仅上传.zip`（88102 字节），不要上传整个 MAS 或 adapter.5 ZIP。技能进入当前登录账号的共享技能库，其他 Bot 可能发现；现役团队不用于试装，同账号另建 Bot 不构成隔离。仅在已确认的采用范围内执行。

本文采用步骤基于旧design2已核成果及已观察入口整理；未留历史操作记录处明确说明，不冒称重演。它只覆盖这一轮已经核实的采用范围，不是全平台总验收，也不把核验限制说成产品不支持。

不要把下面每一步界面或确认顺序都理解成「本轮已经逐步实测过」。已核成果、已观察入口和未留记录的限制，见文末附页。公开候选的文件名、大小和哈希也集中在附页，正文只写怎么做。

配套复制请求见同目录《可复制安装请求.txt》。

## 1. 从哪里开始

打开已登录的 Grok Bot 官方客户端，进入你要安装到的那个目标 Bot 的现有一对一对话。就在这个对话里提供材料、保存和核对。不必为此新建 Bot，也不必使用某个特定测试名，更不要靠新建 Bot 做隔离。

## 2. 提供公开候选包

当前已观察到的附件入口为输入框旁加号（`+`）菜单中的「Attach files」，可由此提供公开候选。保存当次具体上传控件未留记录。

请提供附页中的那一份公开候选包，不要上传带内部说明或测试记录的其他压缩包。包内应有完整 `body.md`，以及 `task-materials/` 下的 `manifest.json`、`LICENSE` 和 `references` 中的四份文件。先让目标 Bot 确认真实结构，并列出它实际看到的附件清单，不要填写任何人的本地目录。

本候选是「完整正文 + 普通任务资料根」这一套独立包装。本版正文的实际保存读回件已经返回并与源逐字核同，旧头部保留；这项新证据独立于旧design2业务结果，不能扩大为完整业务验收。

## 3. 先检查，等你确认后再保存

把复制请求的第一段贴进对话。这一段是给新用户的操作约束，用来避免未确认就保存或覆盖已有技能，并不是对本轮历史操作的逐步回放。本轮没有留下「先完整展示参数、再由操作方确认后才保存」的原始记录，因此不能断言那种确认顺序当时已经实测。

按第一段，目标 Bot 应先做这些事，且先不要保存：

- 核 `candidate_id`、正文和五个资料文件的哈希，并回报。
- 把资料放到它自己云电脑上可读的普通任务目录，报告真实位置。这是普通任务资料根，不是技能私有附件目录。
- 检查当前账号技能库是否已有同名 `solo-to-team-grok`。同版且已核可用则复用，不重复保存；没有可靠同版证据或需要替换时，先核已有对象及差异；已有适用替换授权走下方更新分支，没有授权才先报告并等决定。
- 首次创建时说明作用范围：不另传作用范围，走系统默认；技能进入当前登录账号的技能库，不是某一个 Bot 独占。不要改权限。
- 仅首次创建时写出拟保存内容：技能名 `solo-to-team-grok`；一行使用说明（候选包没有独立的使用说明字段，须由你确认，并提到使用前读取本单任务资料，不要用测试专用句子）；正文必须是完整 `body.md`，不手工补头部、不用更短的子集代替，并给出正文字节和哈希；作用范围不传。

需要首次保存时，你看过后回复复制请求里的确认句，再请它用系统自带的保存技能能力保存一次；已有同版且已核可用则复用，不重复发送保存确认句或再次保存。普通用户不必运行任何接口。保存只做一次。「已保存」一类回执不能单独当作保存完整。

### 已有旧版时：更新原对象

“同名”不足以定位可安全更新的对象。先核唯一真实对象及旧版本，保留可恢复的旧原件与元数据；同版已核可用直接复用。需要更新时沿用已有适用替换授权，范围不清才先说明。

由目标 Bot 核当前原生能力。已留存的 UpdateSkill 帮助区分：写入带既有 id 是重写，省略 id 是创建。更新须用当前实际查到的原对象 id，不猜、不省略，也不另建同名对象。当前接口不同时先核真实契约。名称、原使用说明、原作用范围及其他头部字段保持不变，除非用户明确要求修改；只替换完整 body.md，不套用首次创建的新描述或默认范围，不手改私有技能文件。

更新一次后，从同一对象读回并核正文、对象标识及应保留字段，再继续第4节。目标不清或不能保持原范围，只停写入并报告，普通已授权工作继续。复制请求中有单独的“已有对象更新”段，不使用首次创建确认句。本分支是采用指引；是否实际完成更新仍以当次证据为准。

## 4. 取回核对包，用原生保存存到本机

新建或更新后，把复制请求的第二段贴进同一对话；同版复用可引用已有核同证据，需取回时只读同一对象，不再次保存。请目标 Bot 生成一份核对压缩包，在本对话里作为可下载附件交出。包内应有：

- 从技能库取出的保存后原件
- `manifest.json`
- 五个资料文件
- 一份来源说明：写明磁盘位置来自 Bot 自己的报告；并写明这是库内读出后的打包件，不是工具原始返回

不要改成优先单独交一个技能原文件附件。本轮已走通的取回方式是：按 Bot 自称从云端技能磁盘读出后打进压缩包，再把这个压缩包作为对话附件交出；你用客户端自带的保存对话框把该附件存到本机（例如下载文件夹）。随后忽略宿主自动加在技能原件开头的短头部，只比后面的正文是否与源 `body.md` 一致（字节和哈希见附页）。不要把那段头部原文抄进对外说明。使用说明若与他人不同，整件大小和哈希也会不同，不要拿别人的整件哈希当标准。

下载后的字节若与回报相符，可以核对该附件本身；这不等于已经取得工具的原始返回。

资料仍应在目标 Bot 报告的那个普通任务资料根上可读，并与保存前哈希一致。

## 5. 首次按技能名使用（同一对话，可选）

核对通过后，可发送第三段：仍在同一对话里，按技能名使用 `solo-to-team-grok`，并使用本单刚才报告的资料根。请它说明实际用的是哪个对话上下文、资料是否可读、读了哪些。不要新建席位或群，不要声称已完成独立审核，不要再索要已提供的资料。

如果看不到工具原文，只记它的自报。不要把这次使用写成已经独立证明真实调用成功，也不要承诺会自动加载，或能在新会话里接续。这两项本轮都没有独立证实。
