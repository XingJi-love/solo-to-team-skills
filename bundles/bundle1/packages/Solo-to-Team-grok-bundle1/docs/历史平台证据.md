## 协作验收与接续

这组字段用于真实采用与协作核对，不要求每个简单任务都填整张表，也不是要求四端重做所有旧测试。

| 要核的事 | 怎样记才准确 |
|---|---|
| 技能是否采用成功 | 版本、实际范围、保存/读取结果、可回查依据分别记录；明确失败不能记该版本采用通过；先核实际保存状态，再处理失败步骤，只读核对与失败诊断继续。前置未成导致未执行的项记未测，取消的轮次记取消。 |
| 是否有另一位审核者 | 写可定位的真实执行上下文及证据来源、是否原制作/原复核；宿主有实例/线程ID就保留，无ID不编造。只有角色名或一个对话自问自答不算独审；无法核清写未知。 |
| 审核是否独立 | 由非制作者实际打开同版文件，注明所见材料、是否见制作过程/已有结论；不同上下文不等于账号、记忆或文件权限隔离，也不自动叫盲审。 |
| 文件是否交到 | 区分本机可读、已作为附件发出、原收件位置实际可取得、用户亲自打开。记录依据/时间；用户原话或截图只在实际取得时填写，不能代造。内部可读不冒称本人已看。 |
| 换会话是否成功 | 先声明本题要验的是新子上下文、全新CLI会话，还是用户在客户端新开的聊天，再按该入口验。只交接续材料，让新会话辨认当前版及未完项，不在提示中泄露预期版本答案。 |
| 版本与旧件 | 指定修改只改受影响处，旧件保留。必要时核指纹/差分；能直接打开同版核对时不机械要求每件都算哈希。 |

接续记录最少写：入口类型与是否继承历史、实际收到的文件、识别出的版本依据、保留的旧件、发生过的中断、仍未验证的范围。换新对话只证明接续能力，不证明资料隔离；未测的入口不要借另一个入口的成功代替。

到约定回件节点无响应时，先查本单的现有运行状态和最近成果，发一次针对本单的进度核对；独立工作继续，避免重复派单。只有确认任务归属、且已有适用中断授权时，才使用宿主支持的暂停/中断能力；不抢占、停止或重启其他任务。保留已产文件与中断事实。原执行者能续就续，不能续则明确更换者及依据，提供版本和未完项，不冒充原人复审、不覆盖旧件。不能从一次迟到推定平台故障或自动设置后台定时。

安装失败后，依据用户已有明确授权或新的选择继续普通辅助任务时，单独标记这不是已通过技能采用验收的任务；缺少平台没有提供的调用ID不成为所有普通工作的硬门槛。无法核实多人执行，就按单助手或独立性未证记录。

长任务可作为文本附件配短单行提示，发送后确认附件和要求完整；本项目远端多行逐键输入曾拆条漏发，不泛称中文输入失效。

记录模板：任务与版本｜采用状态及依据｜执行者/可见性｜同版审核入口｜收件状态及依据（用户确认原话仅在实际取得时填）｜接续入口类型｜当前阶段/下一节点｜未知、取消及中断事实。

本次朋友报告的rc3、Codex测试适配与当前候选分别留证；8条回件不是8次独立成功，也不能代替本版四端原生实测。此说明不更改现役团队或授予新增访问。

缺少收件证据时先核已产文件、传输及任务状态，不因未知就原路重派，尤其不重复付款、外发、覆盖等有副作用动作。已授权的接续和换执行者沿用现有授权，不逐次再问；超范围只停受影响步骤。文件真实可读、版本可核的成果，不因缺原始工具日志而作废或重做。
