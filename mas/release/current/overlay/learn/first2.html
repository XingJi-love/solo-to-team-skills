第一次用，先验哪两件

读完这页，你能做两件事：① 拿到一份别人交来的文件，指出哪一格还是错的；② 不开账号、不用模型，把包里的离线小练习做完，再知道怎么准备自己的那半份项目。

先说这页答什么、不答什么

  • 它回应公开仓里两位读者说到的事：issue #7（为什么把「收到成果」和「验收通过」分成两步）和 issue #15（有读者说用本地 Agent 要花 token、买不起，只能用网页版 AI）。这里只指向，不代为回帖。
  • #7 还问了「当初碰到过什么事」。本页不回答这一问，只讲包内留件里真实发生过的事。
  • #15：这页和下面的练习不花 token，用浏览器打开本地文件就行。这不等于本地 Agent 的 token 成本问题已经解决，本页不评估那个问题。
  • 本页是随产品离线打开的发布候选，不提供下载。

第一件：收到了，不等于对了

下面是 WorkBuddy 团队回件里的一次真实往返，来自审核记录（按回件自述转述，回件里对角色的叫法与本页不同，本页用原职官名；页内引号只标出关键词，不是逐字摘录；平台内部过程我们没有独立核实）。题目是一场虚构的街区地图共创工作坊，只用来练习。

  1. 收件。先交的是 20 人的半成品。首席回执：版本 MAP-20-R1，合计 ¥1,349，余 ¥151，待办是「散场收工具责任人未定」，还没开工。这一步只证明双方说的是同一份东西。
  2. 变更。参与者从 20 人增到 24 人，¥1,500 预算和 14:00–17:00 照旧。
  3. 交件。生产官交出 MAP-24-R1：6 张桌，合计 ¥1,464，余 ¥36，场地内 27 人，不超过上限 30。
  4. 退回。审核官打开实物后还是退回了，原因是两个格子。
    • A4 名牌备品 R1 要协调员「应交 6 张」，可同一份 R1 写明这 6 张自 14:00 起由现场志愿者保管、随签到台。协调员照单填，只能写「实交 0、差异 −6」，凭空多出一笔缺。R2 把这格改成「—」，备注志愿者自 14:00 起保管，不纳入这次移交。
    • C7 备用材料（A3 同理）R1 把应交数固定写成「1 套」，可计划允许第二轮动用 1 套备品。用掉以后实点是 0，就会被记成短缺。R2 改成「1 套（未动用）／0 套（已动用，注明桌号与时间）」。
  5. 只改指明处。生产官只改这两个问题和随之要对齐的地方并出 R2（记录报改动 15 处，其中含采纳一条措辞建议），金额和数量一个没动，¥1,464、¥36 照旧。审核官重新打开 R2，重算了全部数，都对，判通过，首席交回。
为什么分两步。收件回答「我拿到的是哪一版、开头几个数是什么」，验收回答「有人打开实物，每一格在现场填得出来吗」。这个案例里，加总全对，两个格子仍然错。只看收到，或者只看加总，都会放过它们。
这是本页对案例的读法，不是审核记录的原话，也不是发起人当初这样分的理由。

拿到文件，先对每一格问两句

  • 这一格写的「应交」，那样东西这时候真在交的人手里吗？（对应 A4）
  • 如果计划内的正常使用发生了，这一格的数还成立吗？（对应 C7）

这两问是本页作者从上面两处退回归纳的，不是审核记录的原话。

第二件：做一遍离线小练习，再备自己的半份

练习是包里的 try-review.html。本页和它放在同一个 learn 文件夹里时，可以直接点这个链接：打开 try-review.html。不联网，不要账号，不用模型。

  1. 打开后点「签收 R1」。这一步对应上面的「收件」。
  2. 选「备品已领用」，点「通过本格点数」，读反馈：R1 里实点 0 减应交 1，是 −1，合法领用被写成了短缺。再点「退修本格点数」对照。
  3. 点「试另一种情况」，情境会自动换成「备品未领用」。再点一次「通过本格点数」：这次点数相符，同一格能签。
  4. 判断之后，页面里才会出现「打开 R1 / R2 原表对照」（换情境后要重新判断一次才再出现）。点开，读 C7 和 A4 的原文。
你该带走的是：同一格，现场情况一变，结论就变。所以验收要问现实，不能只看加总。

再准备你自己的半份项目（也是离线文字活）

照 MAP-20-R1 的样子写成一个文件，每一块都写短：

  • 一个版本号，比如 MY-V1。
  • 已定、不能动的条件。
  • 可以随人数、数量变化的项。
  • 还没做的待办，写明谁来做（这是本页的建议）。

交出去的时候，先单独交这份文件，等对方说出它读到的版本号，再用另一条消息发变更。案例里就是这个顺序。文件交给谁、用什么工具，本页不展开：那取决于你自己的团队和账户，不属于这页的零账号练习。

同包里另有「带底稿开工」入口（打开「带底稿开工」）：在本机打开一个网页，选入自己的底稿，写明任务和验收点，离线生成一个交给你所用 AI 工具（文中称宿主）的项目包，不需要联网、登录或模型。之后把项目交给宿主去办，才会用到宿主自己的模型、费用和权限，本页不展开。

这页不承诺任何结果，也不说明如何获得本包。它只是帮你在第一次用的时候，知道先看哪两处。

First time here: check these two things

After this page you can do two things: ① take a file someone handed you and point to the cell that is still wrong; ② finish the offline exercise in this package with no account and no model, and know how to prepare your own half of a project.

What this page answers, and what it does not

  • It responds to two things readers raised in the public repository: issue #7 (why “result received” and “result accepted” are two separate steps) and issue #15 (a reader says running a local agent costs tokens they cannot afford, so they only use a web-based AI). It only points to them. It does not reply there.
  • Issue #7 also asks what happened to the author that led to the split. This page does not answer that. It only describes what actually happened in the retained case files.
  • On #15: this page and the exercise below cost no tokens. A browser and a local file are enough. That does not mean the token-cost problem of a local agent is solved, and this page does not assess it.
  • This page is a release candidate that opens offline with the product and offers no download.

First: received does not mean correct

Below is one real round trip from a WorkBuddy team’s returned files, taken from its audit record (reported as that record states it; the record names the roles differently from this page, which uses the original officer titles; quotation marks here mark key terms and are not word-for-word quotes; we have not independently verified what happened inside the platform). The task is a fictional neighbourhood-map workshop, used only for practice.

  1. Receipt. The first file sent was the 20-person half-finished draft. The lead acknowledged: version MAP-20-R1, total ¥1,349, ¥151 left, and the open item “nobody is named to collect the tools at the end”. Work had not started. This step only proves both sides are looking at the same file.
  2. Change. Participants went from 20 to 24. The ¥1,500 budget and 14:00–17:00 stayed.
  3. Delivery. Production sent MAP-24-R1: 6 tables, total ¥1,464, ¥36 left, 27 people in the room against a limit of 30.
  4. Returned. The reviewer opened the actual file and still sent it back, for two cells.
    • A4 spare badges R1 told the supplies coordinator to hand over “6 badges”, yet the same R1 says those six sit at the sign-in desk in the floor volunteer’s keeping from 14:00. Filling the sheet as written would give “handed over 0, difference −6”, a loss that never happened. R2 changed the cell to “—” with a note that the volunteer has held them since 14:00 and they are outside this handover.
    • C7 spare kit (A3 is the same case) R1 fixed the expected count at “1 kit”, yet the plan allows the volunteer to use one spare kit in round two. After that, the count is 0 and gets booked as a shortage. R2 reads “1 kit if unused / 0 if used; record the table and time”.
  5. Only what was named changed. Production fixed just those two problems and the places that had to be brought into line with them, and issued R2 (the record reports 15 changes, including one wording suggestion that was adopted). No amount or quantity moved; ¥1,464 and ¥36 stayed. The reviewer reopened R2, recomputed every figure, found them all right, passed it, and the lead delivered it.
Why two steps. Receipt answers “which version do I hold, and what are the headline numbers?” Review answers “someone opened the real file: can each cell be filled in on site?” In this case every total was right and two cells were still wrong. Checking only receipt, or only totals, would have let both through.

With any file in hand, ask two questions of each cell

  • The cell says who should hand over an item. Does that person actually hold it at that moment? (This is A4.)
  • If the planned, normal use happens, does the expected number still hold? (This is C7.)

These two questions were distilled by the author of this page from the two returns above. They are not wording from the audit record.

Second: do the offline exercise, then prepare your half

The exercise is try-review.html in the package. When this page sits in the same learn folder, this link opens it: open try-review.html. No network, no account, no model.

  1. Open it and press the acknowledge button for R1. This is the “receipt” step above.
  2. Pick “Spare used”, press “Accept this count”, and read the feedback: in R1 the counted 0 minus the expected 1 is −1, so a legitimate use is written up as a loss. Then press “Return this count” to compare.
  3. Press “Try the other situation”: the situation switches to “Spare unused” by itself. Press “Accept this count” once more: this time the count matches and the same cell can be signed.
  4. Only after a verdict does “Open the R1 / R2 comparison” appear (after switching situation, give a verdict again for it to reappear). Open it and read the original C7 and A4 cells.
What to take away: for the same cell, the verdict changes when the situation on site changes. So review has to ask about reality, not just add up totals.

Then prepare your own half of a project (also offline, just text)

Write one file in the shape of MAP-20-R1, each part short:

  • A version label, for example MY-V1.
  • The conditions that are fixed and must not move.
  • The items that may change with headcount or quantity.
  • The open to-dos, each with an owner (this is this page’s suggestion).

When you hand it over, send the file alone first, wait until the other side states the version it read, and only then send the change in a separate message. That is the order used in the case. To whom you hand it and with which tool depends on your own team and accounts, and this page does not cover it: that step is outside this page’s no-account exercise.

The same package also has a “Start with your drafts” entry (open “Start with your drafts”): you open a local page, attach your own drafts, state the task and the acceptance points, and it generates, offline, a project package to hand to the AI tool you use (called the host). Building the package needs no network, no login and no model. Only when you give the project to the host to carry out are that host’s own model, costs and permissions involved, and this page does not go into that.

This page promises no result and does not say how to obtain the package. It only helps you know which two things to look at first.
