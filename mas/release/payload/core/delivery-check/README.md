# 交件前对照卡 / Final handoff check

交第一份材料时，把这句话一起发给首席。若这时只要求收件，首席先回执；等用户正式要求制作，再把检查随本单派给生产官和审核官。

<!-- intake-zh -->
> 制作与审核时，请分别核两处：成果若写了生效日期，来源是哪条输入，没有来源就写日期待定；每项改动是否传到所有实际受影响的表格、通知或交接对象。审核官在原审核回复中指出所读版本、来源和核对位置，首席交回同版。
<!-- /intake-zh -->

| 谁来核 | 日期依据 | 变更传到了哪里 |
|---|---|---|
| 生产官，交文件前 | 区分记录日与作业日。只有输入明确给出作业日才填；暂缺就写“日期待定”，其余能做的继续。只有日期挡住实际执行才请首席确认。 | 从旧版到新版列出实际变化的人、事或时间，顺着共用人员、物料和先后依赖再查一层。只更新本次交付里受影响的表格、通知及交接。 |
| 审核官，交结论前 | 亲读成品中的日期措辞，回到原输入找能支持它的句子；文件名、聊天钟点和记录时间只能证明各自的记录时间。 | 打开同一版的总表和已有局部说明，逐项比对受影响对象的值和表述范围。发现“其余不变”时，核对“其余”到底覆盖谁。只修有差异处，复核修订版。 |

审核回复可用一行：**〔版次〕日期〔来源或待定〕；变化〔对象 → 已对齐的具体位置／缺口〕；结论〔通过／退修〕。** 没有日期、通知或这类依赖的任务，按实记“不涉及”，不另造文件。更新交付内的通知文案不等于代用户对外发送。

## English

Send this with the initial brief. If the user requests an acknowledgement only, the lead acknowledges the input first and carries the check forward when production is authorized.

<!-- intake-en -->
> During production and independent review, check the original source for any effective date, mark the date pending if no source sets it, and trace each change into every affected table, notice or handoff. In the existing review reply, name the version, source and locations checked. Return that same version through the lead.
<!-- /intake-en -->

**Producer.** Keep the date a record was made separate from the date work will take effect. If the latter is unspecified, mark it pending and continue feasible work. Compare old and new assignments; follow shared staff, resources and task dependencies to the people and notices that actually change.

**Reviewer.** Open the stated version and its source. Check timing claims against the original wording, then compare affected recipients’ actual instructions with the master table. Test the scope of “all other arrangements remain unchanged.” Record the version, date evidence, affected locations and verdict in the existing review. Mark irrelevant checks “not applicable.” Draft notices stay in the deliverable unless separately authorized for sending.
