# 一人成阵 · 在 DS Bot 里建三席

给已有 DS Bot v0.3.2 的用户。你会得到一个能接单的项目首席、一名生产官和一名独立审核官。现有主 Bot 只负责建队，建好后直接在**新项目首席**的聊天里交任务、取结果。

本包由项目团队独立制作。采用 DS Bot v0.3.2 作者发布的工具接口，已对照源码检查，尚待在该版本中实机试走。启动模型、创建席位后打招呼以及后续办事均可能占用你现有账号的额度，按你的配置计量。

## 你只要做两件事

1. 把整包解压到一个**本次专用的空文件夹**，保留本页、[manifest.json](manifest.json) 和 [三个头像](avatars/) 的相对位置。打开 DS Bot 中有 **Main Bot／主 Bot** 身份的聊天，告诉它解压文件夹的位置。可将文件夹放入主 Bot 已能读取的团队工作区。
2. 把下面这段发给它。收到拟办清单后，核对三个名称、头像、工作目录和预期用量，按清单里的批次确认。也可以选择默认头像。若模型未配置、显示付费升级或要求扩大权限，先停在相应步骤。

> 请从我指定的文件夹读取《开工入口.md》和 manifest.json，按说明先预览三席。我允许你只读核对名单；请仅列本包相关席位、这次拟做的动作与用量提示，等我确认后才建立。本次新席的工作目录都设为这个专用文件夹。若我已有本包建队回执，先按回执核对同批席位。

## 给主 Bot 的建队步骤

**1. 看清目录与身份。** 确认能实际读到两份文件。用 `list_bots({})` 核自己的 Main Bot 身份；仅在输出中对照本项目名称，不转述他人的名单、活动或文件。如果当前不是主 Bot，或缺少 `create_bot`，请用户回到有该身份和工具的聊天。不得直接写 DS Bot 的状态文件。

**2. 列出三席预览。** 本包 JSON 是项目清单。首次取一个短的英数字批次号，例如随机八位；续办时取本批原会话中已确认的号。在三份 `create_bot` 的全部字符串中替换字面量 `{{批次}}`。首席、生产官、审核官均是新的项目席，全部保留 DS Bot 普通 Bot 身份。逐一列出完整名称、拟新建或拟复用、原因和头像选项。

一个席只有在**本主 Bot 原聊天能查到本批同名的成功创建回执**，且本次名单的**全名、岗位、指令首行中的包版本／批次／岗位标记都吻合**时才可复用。续办时先找此前的原生创建结果；找不到时不得把用户的同名席当作本包。发现私密席、同名异源、标记不符、用户改过用途或归属无法核实时，原席不发消息、不改设置、不改名、不删除。新批次用新号重新出预览；同一批次去重。若上一步可能已成功但返回中断，先核原生回执和当前名单，说明尚不确定的席位，不能盲目重建。

**3. 收到该批明确确认，再按席建立。** 请用户确认批次、三席名单、专用目录、搭配本包头像或默认头像。调用前再列一次名单防止重名。逐席读取 JSON 的 `create_bot` 对象，仅提交 `name`、`role`、`instructions`、用户选用的 `avatar`，以及用户已指定的 `work_dir`。指令首行保留归属标记。将 `work_dir` 填为实际专用目录的绝对路径；头像须把清单中的相对路径按**本包所在文件夹**解析成绝对路径，因为宿主会按调用者的当前目录解析。默认头像则省略该字段。用户若选自备图，先确认本地路径和范围，仅处理指定图。不得传入整个 manifest、岗位 key 或虚构参数。模型沿用宿主已配置的默认值，逐席权限由用户自行设置；出现宿主授权提示由用户在原入口决定。

每席只在拿到明确创建结果后记回执。若一席发生错误，保留先前成功项、报出本席实况；恢复后先回读，只补确有缺失的一席。已有匹配席沿用，不调用 `update_bot`。本轮建立三席，不建群、不改既有席位、不启动后台任务。

**4. 回读并交接。** 再用 `list_bots({})` 核三席实际出现的全名、角色、批次与工作目录，在原聊天交回「批次；实际新建/复用；三席名称；未核项」。名单只显示指令首行摘要，无法用它证明全文和头像；如要逐项核，提示用户点开这三席的详情，对照对应指令与头像。把这份回执留在当前聊天，日后可凭它续办。三席齐备时告诉用户进入哪个项目首席聊天。此刻仅完成建队回读，业务交付另有验收。

## 第一单怎么用

点开侧边栏中的 **一人成阵·本批次·首席**，交它一个小任务和允许处理的材料。可以从零开始，也可先交一份半成品，请它回复“我接到哪一版、要交什么”；收到回执后再发一次变更。资料只放在本次专用文件夹，优先用合成练习数据。

三席默认通过 `message_bot` 点对点协作。项目首席按名单中的精确全名派生产官制作，再把**实际产物和版本**交审核官；两次派工均用 `reply_to: "me"`，由项目首席接回。消息里写清文件位置、输入与期望回复，因为收件席看不到派件席的原聊天。用户的变更只交项目首席，首席向受影响的席位接续。派工回执表示已送出，需等相应席位实际回件。

验收时，在项目首席原聊天应能打开最终文件，看到生产官交件版次、审核官实际核过的同版结论；若有退修，还应能对上修订处和复核版本。权限或文件不可用时由负责席回首席说清楚，已验证的部分继续沿用。
