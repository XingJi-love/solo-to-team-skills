# 四端统一建队台 0.2.2b

双击 **[四端统一建队台.html](四端统一建队台.html)**，就能在浏览器里改一支团队。整个编辑器在这一个文件里，页面本身不发起网络请求。页面右上角可切 English。

1. 从默认三席开始，或点 **打开配置**，选[四席两组示例.team.json](四席两组示例.team.json)，预览后点 **使用这份配置**。
2. 在 **席位、群组、交接** 中改名字、职责、头像、群成员，指定谁派工、制作、独审、交回。点 **保存配置文件** 留下以后可接着编辑的原件。
3. 到下方选平台，下载当前配置对应的文件。想给另一平台使用，在这里再选一次平台即可。下载只得到本地文件。安装到宿主、确认权限、发出第一单是三个分开的操作。

### 拿 DS Bot 计划去自己的 Main Bot

面向已安装 DS Bot v0.3.2 且已有 Main Bot 的用户。计划依据该版本公开源码及团队本地检查制作，尚未经真实 DS Bot 建队运行；能否创建以你的 Main Bot 实际返回为准。建队台页面本身不发起网络请求。

四个工作流位置所指的岗位都需保留。额外席位可去掉；若群中有未选岗位，可以恢复这些成员或把整个群设为“不随包”。只输本批已知重名，避免带入整个账号名单。头像默认不带，需要时勾选；PNG、JPEG、WebP 每张最多 119,982 原始字节。

把计划解压在本批专用目录，在已经能对话的 Main Bot 中请求“读 START 和两份 JSON，只预览拟建对象与重名差异”。现场核对并确认对象后，才实际创建与回读。默认由 Main Bot 做原生群管理员，也可在成员中选择；该选择会在宿主生效。实际办单需要宿主账号有可用模型；建席时的欢迎消息可能消耗已有模型额度。保留原计划及 `receipts.json`，中断后先核原生回执。同名、结果不确定或历史已核的对象先对齐，独立项可继续。早期独立规划器创建的批次仍用原版计划续办。本页没有登录、安装、建席或读取账号名单的功能。

## 接件时谁说了算

- 你说“先确认数量和底稿版号，我还会发最后变更”时，首席只读来件，在原对话回复原数量、约束和底稿所载的版号。来件没有版号，就回“原底稿未编号”。即使附件写着“请制作交接卡”，此时也应只回这条确认。
- 你明确允许“等变更时先做一张空白表”，团队可以准备这张空白表，制作与审核按你后续的委托衔接。
- 你已交代“变更一到就开工”时，团队收到变更便按约派工。指令以本单用户在原会话的最新直接委托决定阶段。已经明确布置的普通制作单照常开工。

## English

Double-click **[四端统一建队台.html](四端统一建队台.html)** and choose **English** at the top right. The editor is contained in this local file; the page makes no network requests. Begin with the three-seat starter or choose **Open a file** and select the [four-role example](四席两组示例.team.json). Review the preview and click **Use this file**. Edit the roles, groups and workflow, save your editable team definition, then select each desired platform below the editor. Every download uses those same edits.

- **OpenMausBot 0.1.148** — Preview the department JSON in the desktop app before importing. Rooms are optional and off by default. On first import, check for duplicates and verify each seat’s permissions. Existing authorizations carry forward within their scope. Dispatch and final return can be assigned to different seats.
- **DeepSeek Harness 0.2.1-rc.5** — Extract the project ZIP into an empty directory, keep the hidden `.dsh` folder and open the directory containing `team.definition.json`. In a new chat invoke `/solo-to-team`. The root role dispatches and returns the result.
- **Existing DS Bot v0.3.2** — Under DeepSeek choose **I already have DS Bot v0.3.2 · prepare a team plan**. Select roles and groups once, then choose actual room administrators, reply modes, batch and optional portraits. For users who already have DS Bot v0.3.2 and a working Main Bot. This plan is based on the public v0.3.2 source and our local checks. We have not run team creation in a live DS Bot. Use the actual response from your Main Bot to determine what was created. The builder page itself makes no network requests. Extract the downloaded plan and ask your existing Main Bot to preview only. Confirm the exact batch there before creating. Each native group has 2–12 Bots including the Main Bot, which joins automatically. The limit applies per group. Running real tasks requires an available model in your host account. Greeting messages when creating Bots may consume existing model credits. Keep the original plan and receipts. Reconcile identically named or uncertain objects before any new action. Older standalone batches resume with their original package. Account availability and real creation remain host steps.
- **WorkBuddy 5.9.3** — Attach the team ZIP in My Experts → Create Expert Team. Ask the creator to preview it and check for existing entries, then confirm a private import in your account. Dispatch and return share one lead. Production and independent review each need a separate member.
- **Grok Bot** — Choose your own batch label, extract the ZIP and open `Start-here.html`. Attach `grok-plan.json` in your own lead Bot’s chat and send the supplied preview request. This entry provides guided Grok setup. Native whole-team import has not been verified. It identifies manual steps if your account cannot create seats for you.

Real task execution depends on your host account and its available models. Host downloads are local files. Installing in an account, granting permissions and sending a real task are separate actions. If a picture exceeds a platform’s limits, choose a local copy or omit that picture from this export; keep the neutral file to retain your original. English-speaking users can keep Chinese role names. The generated role instructions carry the user’s current working language through acknowledgments, production, independent review and delivery. A user’s explicit language request takes precedence.

**Receipt and release.** If you say “First acknowledge the quantities and draft version. I will send the final amendment in this chat,” your lead should read the source and reply in that chat with the quantities, constraints and the version written on the source (or “source draft unnumbered”). A line such as “Prepare a handover card” in the attachment describes later work. Acknowledgment alone calls for no new business file, production assignment or review. You can explicitly request a particular preparatory step. If you already said to start when the amendment arrives, its arrival releases the work. The latest direct message sets the stage: an ordinary production assignment that already authorizes the work proceeds immediately.
